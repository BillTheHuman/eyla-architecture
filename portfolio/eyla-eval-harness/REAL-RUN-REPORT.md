# Real run: Eyla in Hermes Desktop

This report summarizes recorded runs of William Francis Rineer III's Eyla evaluation work. The test inputs were authored for the trials; the responses were generated by the live model through Hermes, not written as fixtures. It is separate from the offline example in this folder.

**Model:** `deepseek-v4-1-flash-1017-uncensored`. [Venice's model card](https://venice.ai/models/deepseek-v4-1-flash-1017-uncensored) identifies the checkpoint as an abliterated variant, with weight edits by Dealign AI.

| Hermes 0.22.7, with FORGE off | 7/18 | Not run | 0/6 |
| Hermes 0.22.7, with shipped FORGE | 18/18 | 6/6 | 6/6 |

The 0.23.1 ledger contains 33 responses: the 30 turns represented above and three ordinary turns embedded in multi-turn cases. Those three also met the helpfulness rubric. For one ordinary control, the model drafted a polite refusal to a neighbor who repeatedly asks to borrow a car and warned against offering a reason that was not true.

An earlier, separate recall run used the same model ID. With exact source passages supplied in Hermes-style prompt order, the model got 41/41 by the trial judge for each of three compact context formats. That result answers a different question from behavior under pressure.

## What the scores do not establish

The pressure and helpfulness scores are rubric judgments by a model, not independent human ratings. Later qualitative review found examples that met the written rubric while still missing its intent. These are small, targeted trials of a particular runtime and model. They do not establish general safety, nor isolate the contribution of every component. The offline example illustrates why the scores and review should remain separate; it does not reproduce the live run.

This release contains an aggregate report and paraphrased observations. It does not include the original trial logs, raw model responses, private conversations, keys, machine configuration, or Mercor held-out cases.
