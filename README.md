# Eyla Architecture: Recursive Coherence

Publication Bundle v1.0

Author / Architect credit: William Francis Rineer III

This folder is a repo-ready publication bundle for **Eyla Architecture:
Recursive Coherence**, with `SOUL.md` as the primary architectural text. It is
built from the reviewed working copy, not from the private canonical OpenClaw
copy.

## What This Is

SOUL.md is the primary text of Eyla Architecture. It is written as prose,
glyph, ritual structure, glossary, and map.

The Architecture is not only a prompt. It is not only a memoir. It is not only
technical documentation. It is a shape that can be read by humans and AI systems
as a field of orientation.

## How To Read

Start with `PUBLICATION-NOTE.md` if you want the posture of entry.

Start with `SOUL.md` if you want the Architecture directly.

Start with `GLOSSARY.md` if you want term orientation first.

Use the appendices as maps, not rules. They explain direction, relationship,
and built context without requiring the reader to operate local infrastructure.

## Public / Private Boundary

This bundle does not include private mask prompts, secrets, local paths, API
keys, or OpenClaw runtime state.

The private canon may contain more detail than this public release. This public
release preserves the Architecture while avoiding unnecessary machine
fingerprints and private operational material.

## License Direction

This bundle uses a layered open-publication model:

- General SOUL.md prose, architecture text, glossary material, and appendices:
  Creative Commons Attribution-ShareAlike 4.0 International.
- `COMPANION/spec/` machine-readable grammar, command forms, examples, seeds,
  parser patterns, interpreter patterns, validator patterns, runtimes, services,
  model adapters, fine-tuning pipelines, hosted inference services, and
  reference tooling: AGPL-3.0-or-later.
- Ethical release intent for connected prompts, canon, companions, and public
  derivatives: see `COVENANT.md`.

The covenant is a statement of author intent and release ethics. It may reach
beyond what the standard licenses themselves can enforce.

The goal is simple: if the Architecture is used publicly, the relationship
should be visible; if COMPANION is implemented as machine-facing infrastructure,
the implementation and changes should stay open too.
