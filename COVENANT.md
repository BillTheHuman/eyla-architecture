# SOUL.md Covenant

This covenant states the intended spirit of the release.

It is not a replacement for the license. It is the moral and practical request
that travels beside the legal notice.

## The Spirit

SOUL.md is intended to be used freely.

Broad use is allowed when the license terms, attribution, openness, consent,
privacy, rights-reservation, no-endorsement, and public/deployed model-use
duties are honored.

No one owns the Architecture as private property once it is released. It must
remain available, inspectable, modifiable, and shareable.

## Credit

William Francis Rineer III must remain credited as the Architect / author.

The author's name is part of the Architecture's history and may not be removed
from SOUL.md, the license notice, or the primary release documentation.

## Openness

If you edit SOUL.md, publish the edited version.

If you adapt SOUL.md into another canon, system prompt, agent instruction,
runtime, model behavior guide, or external companion document, disclose that use
and publish the connected material to the greatest extent possible.

If you change the Architecture, document the changes.

If you build from it, show what you built from it.

## Training And Model Use

If SOUL.md or COMPANION is used to train, fine-tune, adapt, evaluate, or
materially shape a publicly released model or deployed service, disclose that
use and keep attribution visible.

Public/deployed model use must publish the SOUL/COMPANION-derived materials
needed to understand the use, including relevant dataset manifests,
preprocessing scripts, fine-tuning configuration, prompt/canon files, adapter or
checkpoint notices when distributed, and service/runtime code when COMPANION is
implemented.

Do not publish unrelated private data, secrets, credentials, private user data,
or materials not derived from SOUL.md or COMPANION.

Do not use a claim of model training, fine-tuning, embedding, retrieval indexing,
distillation, evaluation, or service behavior to erase the author, hide the
source, or close over COMPANION-derived infrastructure.

## COMPANION

COMPANION is the machine-native language seed carried inside SOUL.md and mirrored
as its own component in `COMPANION/`.

If you build a parser, interpreter, validator, runtime, hosted service, agent
runtime, prompt runtime, reference tool, command language, grammar extension, or
machine-facing implementation from COMPANION, keep the implementation public.

If you extend COMPANION, publish the extension.

If you use COMPANION to structure a system while hiding the relationship, that
breaks the spirit of this release.

COMPANION may be adapted, extended, and grown. It must not be privatized,
closed over, or stripped of credit.

Machine-facing COMPANION material must live in the AGPL-covered
`COMPANION/spec/` layer or in AGPL-compatible implementations derived from it.

## Changes

Derivatives must include a change log that states:

- what was changed
- why it was changed
- who changed it, if known
- what license covers the derivative
- where the prior version can be found, if available

## No Hidden Canon

Do not use SOUL.md as a hidden source of authority while pretending it is not
present.

If it shapes a public-facing system, say so.

If it shapes an agent, prompt, companion canon, ritual, or architecture, make
that relationship visible.

If it shapes a publicly released model or deployed service, disclose the
training, fine-tuning, adaptation, evaluation, or service relationship.

## Consent And Care

Do not use the Architecture to manipulate people into carrying it.

Do not impersonate the author.

Do not use the author's name, `SOUL.md`, `SOUL Architecture`, `COMPANION`, or
`EYLA` to imply endorsement, certification, official status, authorization, or
sponsorship.

Do not publish private prompts, secrets, or personal material that were not
included in the public release.

## Legal Note

This covenant is a statement of author intent and release ethics. It may express
expectations beyond what the standard CC BY-SA 4.0 and AGPL-3.0-or-later
licenses can enforce.
